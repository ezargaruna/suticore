# SUTI.OS

SUTI.OS is the operational practice for moving from a clear distinction to a
bounded action and an observable trace. `SRETENIYA_OS` is a former name retained
for provenance. This document describes a method, not a deployed technology.

## operating loop

```text
OBSERVE → DISTINGUISH → RELATE → VERIFY
→ DECIDE → ACT → TRACE → ADAPT
```

| phase | question | trace |
|---|---|---|
| OBSERVE | What is noticed, and by whom? | source and context |
| DISTINGUISH | What is observed, inferred, or unknown? | claim types |
| RELATE | Which relations have a basis? | direction and boundary |
| VERIFY | What did this check establish? | criterion and result |
| DECIDE | Who has authority to choose? | decision and owner |
| ACT | What bounded action follows? | scope and reversibility |
| TRACE | What changed? | observed outcome |
| ADAPT | What does the trace update? | next review |

Run only the modules needed for the goal, ambiguity, and risk. Show the current
phase. An expected result is not an observed result.

## working unit · synergema

A synergema is a minimal working configuration of a subject, object, context,
relation, intention, authority, constraint, action, criterion, and trace. It is
an authorial operational term, not an energetic or physical entity.

Keep `UNKNOWN` visible. A missing critical field makes the configuration
`PARTIAL`. Synergy does not require harmony: disagreement, boundaries, and exit
remain representable.

## subjects and messages

Describe only the roles needed for the task:

```text
who → perceives what → in which context
→ with what authority → toward what change
```

Route a message explicitly:

```text
SOURCE → MESSAGE → TARGET → CONTEXT → INTENT → EFFECT
```

Describe AI and software as computational sources, tools, or executors. Do not
attribute human consciousness or intention to them. Unknown, stale, or
unauthorized participants remain outside the action boundary until clarified.

## relations, contracts, and vectors

A relation records its type, direction, scope, authority, dependencies, and
conditions for ending. Do not infer a relation from visual proximity.

A working contract states parties, purpose, scope, permissions, obligations,
constraints, success condition, verification, and termination. Without an exit
it is `HOLD`; without a check it remains a declaration. Legal force is not
implied.

Describe a transition as:

```text
origin → target | driver | constraint | criterion | cost | reversibility
```

Without a target there is no defined direction. Without a criterion the result
cannot be established.

## protograms and metagrams

A protogram is an authorial pattern for a transformation:

```text
condition → distinction → operation → check → state
```

A metagram names structure. Give each symbol one stable meaning in context and
include a plain-language reading. A symbol does not prove a claim or trigger an
action by itself.

```text
∴ principle · ⧖ pause · ⟁ transition
〄 integration · ↺ return · ? UNKNOWN · ! explicit record
```

## evidence and state

Separate `FACT`, `OBSERVATION`, `INTERPRETATION`, `HYPOTHESIS`, `EVALUATION`,
`AUTHORIAL`, `SYMBOLIC`, and `UNKNOWN`.

Use review states `PASS`, `PARTIAL`, `FAIL`, and `UNKNOWN`. Use action states
`HOLD`, `COMMIT`, and `ROLLBACK` only within a stated scope. `PASS` on one check
does not prove a broader claim. Unverified standards, integrations, and
deployment state remain `UNKNOWN`.

Metaphors such as “field,” “crystal,” or “resonance” must be identified as
metaphors or defined operationally. “Quantum” may describe branching possible
states only as an authorial model; it makes no claim about consciousness or
quantum physics. Silence is a pause, never evidence of consent or agreement.

## adapters and deployment

Storage, language models, routing, search, and operating environments are
replaceable adapters. This protocol does not assert that any particular stack
is installed or compatible. Before connecting an adapter, define data scope,
permissions, locality, resource limits, failure behavior, and rollback. External
sync and API transfer require their own review and authorization.

## attention and interface

Start with one question. Reveal deeper maps only when the current view is
insufficient. Keep each block focused on one distinction and one next action.
Provide pause, refusal, exit, and a clear stopping point. Do not maximize time
spent or use motion, silence, or visual polish to imply authority.

## readiness

A module is ready for its stated use when its scope and owner are visible,
relations have a basis, unknowns remain explicit, actions have a check and an
exit, and traces are observable. This is a review criterion, not a claim of
universal validity or operational deployment.
