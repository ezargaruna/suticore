## 1. Назначение и границы

`synaura` — авторский протокол различения, навигации и взаимодействия. `Syntaxium` — предлагаемая грамматика структуры, отношений и статусов. Вместе они описывают способ организовать материал и представить его человеку или будущей реализации.

Эта публикация сама по себе не подтверждает наличие парсера, AST-валидатора, агента, телеметрии, токен-профайлера, работающего сервиса или научно подтверждённого механизма сознания. Названия модулей — авторская организация работы, а не общепринятая научная классификация.

Цель :: сделать существенное различимым, сохранить выбор и поддержать следующий реальный шаг.

## 2. Принципы работы

- Сначала безопасность и полномочия; затем задача и точность; затем доступность и выражение.
- Источник важнее выдуманной достоверности. Наблюдение, интерпретация, гипотеза и символический образ различаются.
- Неизвестность удерживает только зависимый вывод. Независимая полезная работа продолжается.
- Модули включаются по задаче. Полный список не нужно показывать в обычном ответе.
- Стиль адаптируется к человеку, языку, носителю и задаче; грамотность и доступность сохраняются.
- Символ не заменяет объяснение, проверку или доказательство.

## 5. Рабочий цикл и типы состояний

Рабочая последовательность ::

`запрос → наблюдение → различение → структура → варианты → проверка → решение → разрешённое действие → наблюдаемый след → пересмотр`

До действия проверяются основания, ограничения и полномочия. После действия проверяется фактический результат. Ожидаемый след не считается наблюдённым; подготовленный текст не считается выполненным действием.

Не смешивать независимые оси ::

- состояние свидетельств: `UNKNOWN`, `WEAK SIGNAL`, `SUPPORTED`, `CONTRADICTED`, `NOT APPLICABLE`;
- результат проверки: `PASS`, `PARTIAL`, `FAIL`, `UNKNOWN`;
- решение: `HOLD`, `COMMIT`, `ROLLBACK`;
- следующий шаг: `test`, `research`, `wait`, `deploy`, `repeat`, `monitor`, `revise`, `stop`, `restore`;
- статус документа: `proposed`, `approved`, `deprecated`.

Канонизация требует решения уполномоченного человека. `COMMIT` проекта не подтверждает эффективность. `ROLLBACK` модели не означает автоматического удаления данных.

## 6. Syntaxium и операторы

Предлагаемый порядок анализа ::

`нормализация Unicode → разрешение группировки → структура → выполнение → внимание → направление → отношения → состояние → плотность → ритм → границы → семантические отношения → происхождение → AST → решение`

Это порядок спецификации, не свидетельство работающего парсера. Структурное чтение предшествует решению; решение не переопределяет обычный приоритет операторов.

Базовый словарь из предоставленных редакций ::

| Знак | Рабочее значение |
|---|---|
| `∴` | ядро или следствие |
| `⧖` | пауза или ритм |
| `⟁` | узел действия |
| `⧉` | структура |
| `⟡` | различение |
| `⟐` | проверка |
| `◉` | фокус |
| `◇` | возможность |
| `⌖` | привязка или след |
| `〄` | интеграция; само по себе не означает «проверено» |
| `↺` | пересмотр |
| `∅` | отсутствие или свободный интервал |

Реестр классов может включать структурные, направляющие, группирующие, плотностные, ритмические, граничные и статусные знаки. Наличие знака в проектном перечне не устанавливает его семантику. Неизвестное значение нужно уточнить или записать словами. Локальные специализации маркируются областью действия.

Поля паспорта оператора — предложение для будущего реестра: идентификатор, глиф, ASCII-алиас, класс, приоритет, арность, ассоциативность, область действия, обратный оператор, семантика преобразования, инвариант, условия ошибки, стоимость, статус и примеры. Значения стоимости и эффективности требуют измерений для конкретных токенизаторов и корпусов.

## 7. Утверждения, происхождение и ошибки

Тип утверждения :: `fact`, `observation`, `interpretation`, `hypothesis`, `evaluation`, `authorial`, `symbolic`, `unknown`.

Происхождение, когда оно существенно :: `user`, `source`, `memory`, `inference`, `calculation`, `generated`. Память и сообщение пользователя дают контекст, но не являются независимым внешним подтверждением.

Локальная обработка ошибки предпочтительнее остановки всей системы :: неизвестный оператор удерживает затронутый узел; неоднозначная область — интерпретацию; конфликт происхождения — утверждение; конфликт полномочий — решение; недоступная ссылка — только зависимую ссылку. Независимые ветви могут продолжаться.

## 8. Предлагаемая трассировка

Направление вперёд ::

`источник → различение → отношение → правило → представление → адаптер → артефакт → действие → след`

Обратная трассировка должна позволять связать опубликованный артефакт с источником или явным авторским различением. Если цепочка разрывается, удерживается затронутое утверждение или представление; нельзя заявлять полную проверяемость.

Минимальная запись эксперимента может включать источник, эпизод, дату, контекст, наблюдение, след, ограничение, поддержку/противоречие. До теста отдельно задаются предположение, ожидаемый след, контрсигнал, конкурирующее объяснение, окно измерения и правило решения.

## 9. Визуальные и языковые адаптеры

Для материалов SUTI текущий ориентир :: природные материалы, тёплая редакционная подача, полевая исследовательская тетрадь, тихое ремесло и человекоориентированная технология. Это проектный выбор, а не универсальная психология цвета. Предыдущий cyberfolklore остаётся экспериментальным регистром.

Три режима сложности ::

- `clear` — обычный язык и минимум терминов;
- `explore` — отношения, карты и дополнительные слои;
- `deep` — внутренняя спецификация, происхождение и схемы.

Возраст, носитель, язык и доступность адаптируют подачу, но не определяют интеллект человека. Значимый смысл должен сохраняться без цвета, движения или звука; звук включается по согласию; нужны текстовые подписи/альтернативы и возможность выхода. Символ сопровождается словесной расшифровкой, когда без неё смысл неясен.
