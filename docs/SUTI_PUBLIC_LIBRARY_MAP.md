# SUTIcore · public library map

Status: public derivative · MVP 2026.9  
Purpose: offer a clear, safe entry into the open SUTIcore library.

This document describes the external contour only. Private records, family
information, exact locations, direct credentials, unresolved personal
histories and internal operating protocols do not belong in this library.

## 1. The public promise

SUTIcore helps a person or a project move from an unclear situation to a
workable distinction, a visible action and an honest trace.

The system does not replace a person, make hidden claims about a person, or
present metaphor as scientific fact. It returns choice to the person who uses
it.

## 2. The self-building cycle

```text
notice → ground → distinguish → relate → shape → test → trace → return
```

| Stage | Public question | Safe output |
|---|---|---|
| notice | What is happening? | a short observation |
| ground | What is the context and boundary? | sources, limits, unknowns |
| distinguish | What is the one difference that matters now? | a usable distinction |
| relate | What does it affect? | a small relation map |
| shape | What form can carry it? | a note, map, protocol or practice |
| test | What is the cheapest honest check? | a bounded experiment |
| trace | What changed and what did not? | an evidence note |
| return | What is the next question? | a new, smaller entry |

The person remains the author of the decision. SUTI provides structure,
language and reflection; it does not claim to install a person into a fixed
world order.

## 3. Library layers

```text

03 · relation       people, projects, place and responsibility

```

The layers are navigation aids, not castes or personality types.

## 4. The pearl model

In public language, a “pearl” means a compact, reviewed artifact: a clear
definition, a map, a protocol, a research note or a practice that can be
understood without private context.

An artifact becomes a pearl only when it has:

- a named source and version;
- a stated purpose and audience;
- a visible uncertainty boundary;
- a human-readable next step;
- a review or test note;
- no unnecessary personal or sensitive data.

## 5. Rhythms of living practice

SUTI supports gentle regularity rather than pressure:

- observe and pause before acting;
- plan around real time, energy and responsibility;
- repeat small practices instead of escalating intensity;
- review consent, access and safety regularly;
- seek qualified medical or psychological care when health needs exceed a
  reflective practice;
- stop when a signal becomes intrusive, overwhelming or unsafe.

No protocol in this public library promises healing, energetic effects,
diagnosis or protection from every threat.

## 6. Safety and sensory care

The public interface should prefer:

- quiet defaults and no autoplay;
- visible controls and keyboard access;
- reduced motion support;
- gradual disclosure of complexity;
- clear status text beside colour;
- no coercive urgency or hidden tracking;
- a simple route to stop, leave or ask for help.

Security is practical: minimise data, avoid secrets, keep dependencies small,
review external links and preserve a rollback path.

## 7. Public repository topology

```text

├── assets/                 local presentation assets
├── protocols/              reviewed open protocols
├── docs/                   public explanations and research notes

├── core/                   implementation layer; publish only after review
└── apps/                   executable projects; publish only after review
```

The landing page is the витрина, not the whole internal system. A file is not
public merely because it exists in a Git branch. Each addition needs a source,
audience, privacy review and a reversible publication decision.

## 8. Contribution rule

Before adding an artifact, answer:

1. What situation does it help with?
2. What is observed, what is interpreted and what remains unknown?
3. Which people could be exposed by publishing it?
4. Can the same value be offered as a smaller redacted derivative?
5. How can a reader test, correct or withdraw it?

Open means inspectable and accountable. It does not mean that every private
source, draft or inner protocol must be exposed.
