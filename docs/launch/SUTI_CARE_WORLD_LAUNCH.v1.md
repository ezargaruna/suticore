## one-sentence offer

**SUTI.world helps a person or team put a tangled question into clear words, see the useful connections and choose a next step.**

First entry is free and self-guided. Personal and team work is a separately scoped service with an agreed price before it starts. No entry fee, referral commission, percentage cut, paid recruitment ladder or fee for questionnaire answers. People who do contracted work receive their agreed payment directly under the written terms. A payment-provider fee, if one is later used, must be disclosed before payment or included transparently in the price.

This describes current intent. A link or product name does not prove a staffed care service, installed AI agent, subscription, human response or working payment route.

## offer paths · no commission layer

```text
free open material → optional private practice → person chooses what next
                                           ├─ stop or keep it private
                                           ├─ ask for a human service, if capacity is open
                                           └─ commission a named fixed-scope service
```

**Open** :: released guides and self-guided practices, no account required.<br>
**Studio** :: a single fixed-scope session, class or audit from the published rate card.<br>
**Private** :: confidential project work only after a signed scope, named data route and retention terms.<br>
**Recurring** :: do not sell a subscription until there is a specific recurring deliverable, actual capacity, clear cancellation and a tested payment route. No subscription to care access, volunteer availability or access to another person's answers.

**Contribution path** :: the person may choose a finite public task such as checking one public link, reviewing a released translation or testing keyboard access. Publish a task card with owner, scope, time, rights and payment. For this pilot, the default is a direct fixed fee in ordinary currency when work is contracted. No commission on a person's network, no cut from a participant's client income, no payment for recruiting and no SUTI Coin for form answers or private disclosures. Contribution credits remain inactive until their own governance and accounting review.

## low-bandwidth and offline architecture

Current measured source sizes in this repository are about 360 KB for `index.html`, 52 KB for `nitya-atlas.html` and 3.7 KB for `library.html`, before transfer compression. Keep CSS and JavaScript inline on the simple static route; use system-font fallbacks, local assets, lazy-loading for nonessential media and no automatic audio/video, analytics, third-party widgets or AI calls. Current known homepage dependencies include a remote font and images; the mirror task is to make those local relative paths and verify the build copies them.

Recommended sequence ::

1. keep GitHub Pages as the canonical public static copy while verifying the exact deployment branch and custom domain;
2. publish a dated downloadable static bundle with local assets, SHA-256 and one-page print sheet; this is the first real offline route;
3. add an optional service worker only after cache-version, clear-cache, update, language-route and privacy tests; it must cache only public static files and never questionnaire answers;
4. consider one Russian-hosted static mirror only after a provider and actual accessibility need are verified from consenting users in Irkutsk and other test points;
5. publish the mirror URL, build hash and last-checked date on the primary page. Mirrors are read-only identical copies, not separate services or databases.

GitHub Pages supports custom domains and HTTPS, but that does not guarantee reachability from every provider or region. Test from actual networks. Do not imply that a second server bypasses a block or guarantees delivery. Avoid wildcard DNS; verify domain control and HTTPS before use. A custom domain and mirror require an owner, registrar access, renewal plan, deploy key policy, monitoring and an exit route. Do not purchase a new domain until existing domain ownership, budget and host choice are checked. See [GitHub Pages custom-domain guidance](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site) and [HTTPS guidance](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https).

No-interconnection path :: a printable card and downloaded HTML are usable when a person has no connection. A mirror only helps when some network path remains available. Do not carry or synchronize personal intake data in the static bundle.

### Russia data boundary

The public NITYA route is local-only. The separate Google Form is a data collection route. Before promoting it to people in Russia, identify the legal operator, all fields, storage/processing locations, access roles, purpose, retention/deletion and consent wording. Article 18(5) of Russia's 152-FZ sets requirements for databases used when collecting personal data of Russian citizens, subject to statutory exceptions; cross-border processing has separate conditions. This design note is not a legal opinion. Do not copy responses to a Russian mirror or another provider until counsel has confirmed the actual arrangement. ([152-FZ, current text](https://www.consultant.ru/document/Cons_doc_LAW_61801/cbf4e15b7c330f9372e876cdf2bc928bad7950ef/))
